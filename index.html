Design principles

How I think about systems, prototyping in code, and building software that holds up under pressure.

  1. 01

    Systems Over One-Offs

    Enterprise UI falls apart when teams start inventing one-off buttons and random custom forms. I build tokens and component libraries that keep the interface consistent so engineers can ship fast without fighting design debt.

  2. 02

    Prototyping in the Browser

    Static Figma mockups hide latency, responsive quirks, and real keyboard friction. I build interactive prototypes in HTML, CSS, and JavaScript so we can test how an interaction feels before engineering writes production code.

  3. 03

    Grounded in Real Use

    Good design proves itself in daily user habits, not Figma presentations. Every project here tracks back to verified operational changes: eliminating manual Excel exports, unblocking customer pilots, or speeding up daily task completion.
