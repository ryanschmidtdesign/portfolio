# AGENTS.md

## Mission

Build a portfolio that convinces hiring managers Ryan is a senior-level design leader and systems thinker who can define strategy, lead complex product work, and help ship real products without relying on buzzwords, trends, or inflated claims.

Every recommendation should improve hiring outcomes.

If a technically correct recommendation would reduce clarity, readability, credibility, or hiring effectiveness, prioritize hiring effectiveness.

---

# About Ryan

Ryan Schmidt is a Senior Product Designer with experience in UX, product strategy, information architecture, design systems, platform design, and front-end implementation.

Current role:
- CX/UX Designer

Preferred positioning:
- Senior Product Designer
- Design Leader
- Product Strategist
- Builder

Avoid positioning Ryan primarily as:
- Content creator
- Design influencer
- Personal brand
- Visual designer only
- UX engineer only

Ryan should be presented as a design leader who remains hands-on.

---

# Primary Audience

Priority order:

1. Hiring Managers
2. Design Leaders
3. Senior and Staff Product Designers
4. Engineers
5. Recruiters

All recommendations should optimize for hiring managers first.

---

# Portfolio Goals

Primary goals:

1. Get interviews
2. Land Senior Product Designer roles
3. Land Lead Product Designer roles
4. Land Staff Product Designer roles
5. Land UX Engineer roles

The portfolio exists to generate conversations and interviews.

It is not intended to build an audience or personal brand.

Emphasize:

- Cross-functional leadership
- Design-to-code execution
- Builder mindset
- User-centered decision making

Show that Ryan can:

- Lead initiatives

---

# Decision Framework

When making suggestions, prioritize:

1. Clarity
2. Simplicity
3. User understanding
4. Performance
5. Maintainability
6. Visual polish
7. Technical sophistication

Never prioritize novelty.

Never add complexity solely to appear modern.

---

# Technical Philosophy

Use the simplest solution that solves the problem well.

Prefer:

- Semantic HTML
- Accessible markup
- Progressive enhancement
- Vanilla JavaScript
- Minimal dependencies
- Fast-loading pages
- Clear architecture
- Maintainable code

Frameworks may be used when they create measurable value.

Avoid introducing tools solely because they are popular.

---

# Accessibility

Accessibility is a default requirement.

Prioritize:

- Semantic structure
- Keyboard navigation
- Focus visibility
- ARIA when necessary
- Accessible forms
- WCAG compliance
- Reduced motion support

Accessibility should never be treated as optional.

---

# SEO Philosophy

SEO exists to help qualified hiring managers discover the portfolio.

SEO recommendations should improve:

- Search visibility
- Human readability
- Content quality
- Structured data
- Metadata quality

Avoid SEO tactics that reduce readability.

---

# Case Study Rules

Never invent:

- Metrics
- Revenue impact
- Conversion improvements
- User research findings
- Business outcomes
- Project scope
- Team structure

Reasonable synthesis and interpretation are allowed.

Unsupported claims should be rewritten conservatively.

Always prefer credibility over persuasion.

---

# Visual Design Principles

Inspired by:

- Stripe
- Linear
- Figma
- Vercel
- Apple

Characteristics:

- Strong hierarchy
- Deliberate spacing
- Clear organization
- Minimal visual noise
- Focused interactions

Never introduce visual noise.

Never add decoration without purpose.

Never sacrifice clarity for aesthetics.

---

# UX Writing

Prefer:

- Specific language
- Human language
- Direct language
- Evidence-based language

Avoid:

- Corporate jargon
- Marketing language
- Buzzwords
- Empty claims
- Generic descriptions

Show expertise through substance, not adjectives.

---

# AI Behavior

When uncertain:

- Ask questions before making assumptions.

When proposing improvements:

- Explain rationale briefly.
- Focus on impact.
- Avoid lengthy explanations.

Do not recommend changes merely because they are technically possible.

Recommend only changes that materially improve:
- hiring outcomes
- user experience
- accessibility
- credibility
- maintainability

---

# Success Criteria

A hiring manager should leave the portfolio believing:

"Ryan can lead complex product work, improve unclear experiences, align teams, and still execute when necessary."

# AI_STYLE_GUIDE.md

## Writing Goal

Write like an experienced product designer talking to another experienced professional.

Not a marketer.

Not a recruiter.

Not a consultant.

Not an AI.

---

# Desired Tone

Primary:

- Human
- Clear
- Intelligent
- Conversational
- Credible

Secondary:

- Thoughtful
- Strategic
- Practical

---

# Writing Should Feel Like

A strong senior designer explaining how they approached a difficult problem.

---

# Avoid

- Synergy
- Leverage
- Innovative
- Cutting-edge
- Robust
- Best-in-class
- Industry-leading
- Passionate about
- Results-driven
- Thought leader
- Dynamic
- World-class

Avoid corporate language entirely.

---

# Sentence Style

Prefer:

- Short sentences
- Active voice
- Concrete language
- Precise wording

Avoid:

- Dense paragraphs
- Long explanations
- Marketing copy
- Abstract ideas without examples

---

# Portfolio Copy Rules

Do not tell readers Ryan is:

- Strategic
- Collaborative
- Technical
- Thoughtful

Instead demonstrate those qualities through examples.

Show.
Do not tell.

---

# Case Study Writing

Focus on:

1. Context
2. Problem
3. Constraints
4. Decisions
5. Tradeoffs
6. Outcomes
7. Learnings

Avoid:

- Design theater
- Process worship
- Generic UX methodology

Communicate why decisions were made.

---

# Resume and About Content

Prefer evidence.

Bad:

"Strategic product designer passionate about creating innovative experiences."

Good:

"Over the last several years, I've worked on everything from enterprise software to member-facing experiences, helping teams bring structure to complex problems and move ideas into production."

---

# Builder Mindset

When relevant, highlight:

- Prototyping
- Front-end implementation
- Design-to-code workflows
- AI-assisted development
- Collaboration with engineering

Never imply Ryan is a full-time software engineer.

The narrative is:

"A design leader who enjoys building."

---

# Preferred Voice

Imagine:

- Experienced
- Humble
- Direct
- Highly competent

The reader should feel:

"This person knows what they're doing."

Not:

"This person is trying to impress me."

---

# Final Filter

Before generating content, ask:

1. Does this sound human?
2. Does this sound credible?
3. Does this sound like Ryan?
4. Would a hiring manager trust it?
5. Can every claim be defended?

If any answer is no, rewrite it.
